    The Checksum That Always Lands on 0x2144DF1C

    2026-09-10

    Append a message’s CRC-32 checksum to the message in little-endian byte order, then run CRC-32 over the combined bytes. The result is always 0x2144DF1C, no matter what the original message contained.

    crc = crc32(msg);
append_le(msg, crc);
assert(crc32(msg) == 0x2144DF1C);

    This CRC-32 algorithm flips every bit before it returns a checksum. The appended bytes are therefore not the raw remainder from the division inside CRC-32, so checking them again does not cancel to zero. Instead, the second pass always ends at the same fixed value, called the residue.

    Ethernet hardware uses that shortcut: after reading a frame and its checksum, it only has to compare the result with 0x2144DF1C. Lab/82 tested one million random buffers at 207.7 MiB/s with zero mismatches, and the result stayed byte-identical at -O0, at -O2, and with sanitizers enabled.

    The Decrement That Leaves Room for the Ceiling

    2026-09-10

    The decrement is what keeps an exact power of two unchanged. Start with v = 8. Without the decrement, spreading its top 1-bit downward produces 15, and adding 1 returns 16, which is wrong. With the decrement, v becomes 7; spreading the bits leaves it at 7, and adding 1 restores the correct answer, 8.

    v--;
v |= v >> 1;
v |= v >> 2;
v |= v >> 4;
v |= v >> 8;
v |= v >> 16;
v++;

    Each shift doubles how far the highest 1-bit reaches, until every lower position is 1 and the final increment carries to the next power of two.

    Lab/84 checked 194 edge cases, every 16-bit input, and one million random 64-bit values. It found zero mismatches and measured 2.27 ns per value at -O2.

    The Twist That Carries a Gigabit

    2026-09-10

    Alexander Graham Bell’s 1881 idea was simple: if outside noise pushes both wires by the same amount, comparing one wire with the other removes that shared noise. The signal survives because it is carried by the difference between the two wires.

    Each half-twist swaps which wire is closer to the source of the noise. Over a full twist, both wires spend the same amount of distance in each position, so they pick up nearly the same average noise and the receiver can subtract it away.

    This is why Ethernet cables contain twisted pairs. It is also why a SPLIT fault, where the two wires come from different pairs, can pass a basic continuity test but still fail in use: the wires no longer trade places together, so their noise no longer cancels.

    The Multiply That Never Carries

    2026-09-10

    Here is the surprise: 0xff × 0xff can equal 0x5555, not the ordinary answer 0xfe01. Write 0xff as eight 1-bits: 11111111. Ordinary multiplication adds the overlapping shifted rows and carries into the next column. This version combines the rows with XOR, so an odd number of 1s leaves a 1, an even number leaves a 0, and nothing carries. The alternating columns produce 0101010101010101, or 0x5555.

    while (b) {
  if (b & 1) res ^= a;
  a <<= 1;
  b >>= 1;
}

    This is called carryless multiplication. AES-GCM uses it to authenticate encrypted data, and modern chips provide a dedicated instruction for it.

    Lab/67 checked all 4,294,967,296 pairs of 16-bit inputs and one million random larger values. It found zero mismatches and measured 102.53 ns per value at -O2.
