The Four Legal Ways to See Memory 

 2026-09-11 19:26 EDT 

 Four bits at the top of the satp register choose the machine's whole memory model. On RV64 exactly four encodings are legal: 0 is Bare, no translation and no protection at all, and 8, 9, and 10 are Sv39, Sv48, and Sv57, page-based virtual addressing with 39, 48, and 57-bit address spaces. The other twelve are not memory models: 1 through 7 and 12 through 13 are reserved for future standard use, 11 is reserved for an Sv64 scheme that does not exist yet, and 14 and 15 are designated for custom use. 

 Sixteen positions, only four are legal 

 Why validate a table? Because legality is not the same as support. The spec says an implementation is not required to support every MODE setting, and that writing an unsupported one has no effect at all. An earlier module probed which MODE values one QEMU model actually accepts; this module validates the table itself, the full set of legal values before any one machine narrows it. And the two sides of the check are deliberately shaped nothing alike: the implementation is a range predicate, mode is 0 or in 8 through 10, while the oracle is a 16-row table transcribed by hand from the spec's Table 114, the document's own row text quoted in the comments. Agreement between two differently-shaped descriptions proves the rule, not shared code. 
 The whole implementation is one line: 
 int satp_mode_legal_rv64(uint64_t mode) {
 return (mode == 0) || (mode >= 8 && mode <= 10);
} 
 The oracle is the opposite shape: an explicit 16-entry list, each row transcribed from Table 114 with the document's wording in the comments. The six rows that never fit in four bits, 16, 17, 31, 32, 100, and 0xFFFFFFFF, have no table row covering them, and the function must judge each one illegal. Running them is what separates a test of the table from a test of the function: the table cannot be wrong about values it never lists. 
 Value 11 gets the same verdict for the opposite reason. The pinned release reserves it for an Sv64 scheme to be defined in a later version of the specification, so the module quotes the release version and counts it illegal, and a future spec version will change that verdict explicitly. The module also corrected its own planning note on the way in: the backlog gloss labeled value 9 as Sv40, but the document's row reads Sv48, page-based 48-bit virtual addressing, and the code, the oracle, and the proof all follow the document. Twenty-two checks, zero mismatches, and one checksum identical across the -O2, -O0, and sanitizer builds, the byte-level signature that all three builds agreed on every verdict. 
 One sentence to carry away: four bits choose the machine's whole memory model, and this validator agrees with the spec's table on every value the field can hold, plus six it cannot.
